# 甲骨文未释字：字形驱动的 AI 辅助考释（方法与已标定原型）

编制：2026-10-02 ｜ 语料：OBIMD（CC-BY-4.0，10,077 片）

> **核心修正**：不再用字符编码"读"甲骨文。甲骨文字形不在 Unicode 里——殷契文渊用私有码位（U+F0000 区），OBIMD 用哈希标签。**唯一可靠的做法是从图像上取字形、用图像做比对。**

---

## 一、为什么必须走图像

| 编码路径（弃用） | 图像路径（采用） |
|---|---|
| `Label` / `codepoint` 是字符串 | 拓片/摹本上像素对齐的字形框（`Position`） |
| PUA 码位无语义，无法比对 | 可以直接算形近度 |
| "同槽位"只能推出语法角色 | 能直接回答"这个形像哪个已识字" |
| 无法处理未编码字 | 对未编码字一视同仁 |

**实测数据**：OBIMD 的 `Main-character.json` 中 3,936 条，1,159 条无隶定；字形图像包覆盖 **1,728 个字形类、10,364 张 PNG**；匿名字形平均只有 **3.4 个字形**，而已释字平均 **27.0 个**——**差 8 倍**。这就是"读不出来"的物理原因：不是算法不够强，是这个形本身就那么几个样本。

## 二、五阶段流水线

```
阶段 0  语料准备
        OBIMD → 按 OrderNumber 重建辞例（20,921 条含标签辞例）
        → 字形类频次（1,730 类）→ 匿名字形（243 类）

阶段 1  可考性分层（对应「孤证不立」）
        按语料实际出现次数分层：
          1 次   161 类   ← 只能靠字形，不能靠辞例互证
          2 次    28 类
          3–9 次  43 类
          ≥10 次  11 类

阶段 2  辞例证据
        平行辞例检验：同长度、其余位置【必须全部是已释字】、同位为已释字
        → 161 个 hapax 中 26 个（16.1%）找到合格平行辞例

阶段 3  字形证据（本版新增，核心）
        3.1 从 Sub-character Images.zip 取每个字形类的真实字形图
        3.2 归一化：反相 → 裁墨迹外框 → 等比缩放 → 居中 → 48×48 二值
        3.3 特征：IoU + 余弦 + 行/列投影轮廓 + 墨量比 + 长宽比
        3.4 在 3,168 个已释字形中检索最相似者
        3.5 生成对照图供人工目验

阶段 4  音韵证据
        zdic 上古音（黄侃/王力系统）——覆盖 1,079 字
        校验：屯/春 同文部 ✓、徹/歲 同月部 ✓、貞 耕部 ✓

阶段 5  证据装配与分级
        输出 [机器可证] / [需人工判定] / [本语料不可证] 三类标注
```

## 三、方法可靠性标定（这一步不可省）

**问题**：形近检索的第一名，可信吗？

**做法**：留一法——拿已释字当查询，看它能否检索回自己的类。**若已知字都找不回自己，结果就不可信。**

### 3.1 摹本字形（字形包）— 主结果

| 指标 | 数值 |
|---|---|
| 查询数 | 584 |
| **Top-1 命中率** | **78.9%** |
| Top-5 命中率 | 83.0% |
| MRR | 0.811 |
| 正确类领先次名的分数间隔（中位） | 0.403 |

### 3.2 摹本字形 — 严格对照（与候选同分布的 200 类）

| 指标 | 数值 |
|---|---|
| 查询数 | 131 |
| **Top-1 命中率** | **32.8%** |
| Top-5 命中率 | 51.1% |
| MRR | 0.423 |

**两个数字为何差这么多**：3.1 的参考库有 1,878 个字形、覆盖 1,721 类，类别之间差异大；3.2 只在同分布的 200 类里做，**近形类多得多**（夨/天/大、户/尹、宅/寢…），难度接近真实使用场景。

> **应采用 3.2 作为可靠性基准：top-1 ≈ 33%。**
> 这意味着形近检索**只能用于把候选排到前面**，不能直接当结论。

### 3.3 原拓切字 — 见第五节，本版实现失败（top-1 6.0%）

## 四、强候选（形似 ≥0.70 且领先次名 ≥0.10）

> ⚠️ **先读这条**：检索 top-1 的标定准确率是 **32.8%**（见 3.2）。也就是说，**这三个候选里大约只有一个是真的，另外两个很可能是"近形类"造成的假阳性**。本节的清单是**排序结果**，不是结论。

全库 243 个匿名字形中，只有 **3 个**通过这个门槛：

### 候选 1｜󺆑 → 「史」　形似 **0.822**（次名 中 0.622，领先 0.200）

- **辞例**（语料共 2 次）：
  - 片 H15410：`貞 用 □`
  - 片 H32813：`卜 王 比 侯 □`
- **字形**：该形为"竖笔＋封闭方框"，与「史」的甲骨文形态（竖笔＋方框，方框为简化的弓形）高度吻合；对照图中「中」「貯」明显不同。
- **音韵**：史 = 黄侃 心母咍部／王力 山母之部（供参考，本字无音）
- **⚠️ 必须先查这一点**：「史」**本身已在字表中**（label=h3nw474wwr，出现 173 次，131 种框架）。所以这不是"新字"，而是**「史」的一个异体形**——正对应奖项体系里"对存争议字作新释读"那一类（二等奖），不是一等奖。
- 对照图：`result/glyph_match/fybnj2savm.png`

### 候选 2｜mepmffeebh → 「寅」　形似 **0.773**（次名 弋 0.640，领先 0.132）

- **辞例**：语料出现 **37 次**，是三个候选里证据最多的
- **字形**：未释形为"上作箭头／矛头，下作环状"，与「寅」的甲骨文形态接近
- **音韵**：寅 = 黄侃 影母先部／王力 餘母真部
- **⚠️ 存疑点**：对照图中未释形与第一张参考图几乎完全重合，而后面几张的「寅」变体形态差异较大。**需要确认第一张参考图是否确属「寅」**（已释字内部变体差异本就很大，这一点必须人工核）
- 对照图：`result/glyph_match/mepmffeebh.png`

### 候选 3｜󳦑 → 「大」　形似 **0.749**（次名 汏 0.647，领先 0.102）

## 五、诚实边界（含一个失败的尝试）

### 5.1 两种字形来源的对照实验（结论与直觉相反）

用户提出的做法是"从原拓按 Position 切字"。我实现了，并做了留一法标定：

| 字形来源 | Top-1 | Top-5 | MRR | 领先间隔（中位） |
|---|---|---|---|---|
| **字形包摹本**（`Sub-character Images.zip`） | **32.8%** | 51.1% | 0.423 | −0.048 |
| **原拓按 Position 切**（`rubbing.zip`） | **6.0%** | 10.5% | 0.103 | −0.091 |

**结论：原拓切图这一版实现是失败的。** 6% 的 top-1 低于随机水平，领先间隔为负（正确类的分数常低于错误类）。

**原因诊断**：拓片是照片——有纸纹、墨色不均、破损噪点、边缘洇墨；摹本是专家描的二值线图。我用的归一化（反相 + Otsu 阈值 + 裁外框 + 缩放）对前者远远不够。**预处理质量的影响大于图像来源本身。**

**这不代表原拓路线错，而是说明**：要走通原拓，必须先解决拓片的**去噪、网格化、笔画细化**（例如用形态学开闭运算 + 连通域过滤 + 骨架化），而不是直接阈值化。这是一条独立且不小的工作。

**因此**：第四节给出的候选结果，其"形"这一类的证据来自**摹本**，可靠性以 32.8% 的 top-1 为准——**只能用于排序候选，不能作为判定依据**。

### 5.2 可证实 / 不可证实

#### [机器可证]
- 字形类覆盖数与频次分层（1,730 / 243 / 161 等）
- 图像检索方法的可靠性区间（摹本 32.8%、原拓 6.0%）
- 每个候选的形似分数、次名、领先间隔
- 平行辞例的存在性与片号
- 假设读法代回语料后的套语命中次数

#### [需人工判定]
- 笔画连接方式是否同构（机器只能比像素分布，不能判笔画）
- 该形是否已有著录与旧释（查《甲骨文字编》《新甲骨文编》）
- 类组归属与互补性
- **第一张参考图是否确属该字**（候选 2 的关键存疑点）

#### [本语料不可证]
- **OBIMD 无类组/时期标注**——而类组正是蒋玉斌「蠢」与陈剑「徹」两项一等奖的胜负手。**此缺口无法在 OBIMD 内部补齐。**
- 161 个只出现一次的匿名字形，无法用辞例互证（孤证）
- 拓片原图路线的可行性，在当前预处理水平下不成立（见 5.1）

## 六、下一步（按价值排序）

1. **重做拓片预处理**：形态学去噪 + 连通域过滤 + 笔画骨架化，而不是简单阈值化。目标是把原拓路线的 top-1 从 6% 提到摹本水平以上。**这是当前最该做的事**，也是让"形"这一类证据真正立在原始材料上的唯一途径。
2. **接类组数据**：从《合集》片号反查类组，把"类组互补"这条判据接进来。
3. **改进检索模型**：当前用的是手工特征（IoU/余弦/投影）。换成字形专用的 CNN 或自监督表征（OBIMD 自带 MoCo 训练配置），预期能把 top-1 显著推高。
4. **人工审阅包**：把 3 个强候选 + 26 条平行辞例假设做成对照册（拓片图、摹本图、辞例、片号、音韵），交古文字学者。
